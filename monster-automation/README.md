# Monster Automation для Cursor

Один пакет для всех сотрудников, **отдельный персональный ключ для каждого**. После установки команды доступны через `/` во всех локальных проектах Cursor. Ключ разрешает доступ к MCP, а не скачивание пакета. Без действительного ключа сценарии не запускаются.

Публичный репозиторий плагина: https://github.com/monster-automation/plugin  
В репозитории нет ключей и полных сценариев — только ярлыки команд.

## Установка сотруднику

Рекомендуемый путь — из GitHub, без терминала и Node.js.

1. Откройте Cursor → **Customize** → **Plugins** → **+ Add** → **From GitHub Repository**.
2. Вставьте адрес: `https://github.com/monster-automation/plugin`, нажмите **Import**.
3. В списке плагинов нажмите **Install** у Monster Automation (для себя — User).
4. В Monster Automation → **MCP-доступ** выпустите персональный ключ. Он показывается один раз, действует 180 дней. Сохраните его в менеджере секретов, не в чат агента.
5. В плагине нажмите **Configure** и вставьте ключ. В Agent-чате введите `/ma-help`.

Если плагин уже стоит, ключ меняется только через **Configure**. Новый ключ ради обновления ярлыков выпускать не нужно.

### Запасной путь: архив из кабинета

Если GitHub-установка недоступна: скачайте архив в кабинете, распакуйте, выполните `node install.mjs` и введите ключ скрыто в терминале. Нужны Node.js 22+ и разрешённые локальные плагины Cursor. Затем **Developer: Reload Window**.

### Если политика компании блокирует установку

В Teams/Enterprise администратор должен разрешить установку плагинов с GitHub / локальный импорт. Установленный из marketplace плагин с тем же именем имеет приоритет над локальной копией: не устанавливайте оба варианта одновременно.

### Безопасность ключа

- Ключ задаётся лично в **Configure** или вводится установщиком в личную копию плагина. Это не общее командное значение и не файл в GitHub.
- Не отправляйте другим людям установленную папку, её `mcp.json` или резервную копию.
- Один сотрудник — один ключ. Клиентские аккаунты не поддерживаются.

## Команды

| Команда Cursor | Для чего |
| --- | --- |
| `/ma-help` | Выбор сценария |
| `/ma-checkup` | Проверка настройки Cursor: что лишнее, что отключить. Правки только после подтверждения |
| `/ma-idea-to-plan` | Идея → план |
| `/ma-design-screen` | Дизайн экрана |
| `/ma-revise-project` | Сверка проекта со стандартами |
| `/ma-product-pass` | Ревью и упрощение продукта |
| `/ma-signoff` | Продуктовая приёмка |
| `/ma-deploy` | Подготовка и выполнение согласованного релиза |
| `/ma-seo-geo-audit` | SEO + GEO аудит |

Например: `/ma-checkup` — отчёт по настройке без правок. `/ma-deploy только подготовка, без push и production-деплоя`. По умолчанию `/ma-deploy` ведёт к живому проду. `/ma-product-pass` без зоны проходит весь продукт.

Команды запускаются только явно. Выбор `/ma-deploy` сам по себе не подтверждает push, выкладку, завершение задач или сообщение клиенту.

Плагин содержит только короткие инструкции запуска. Полные сценарии загружаются через MCP при каждом запуске. Внешние skills (`ponytail`, `react-doctor`, `agent-browser` и другие) устанавливаются **отдельно**.

## Обновления и замена ключа

- **Текст сценария или стандарт:** администратор деплоит приложение. Переустанавливать плагин не нужно.
- **Новая команда или ярлык:** снова **+ Add → From GitHub** / обновить плагин из того же репозитория. Ключ в Configure сохраняется.
- **Истёк или отозван ключ:** выпустите новый в кабинете и замените его в **Configure**. После проверки отзовите прежний.

Начиная с плагина **1.1.0**, каждая `/ma-*` команда проверяет версию ярлыка. При обязательном обновлении агент остановится и предложит взять пакет с GitHub.

## Если не работает

- Команд нет: перезапустите окно Cursor, проверьте Plugins и Configure.
- `401`: срок, отзыв или ошибка ключа. Замените ключ в Configure. Не присылайте ключ в поддержку.
- `403` или пустой список проектов: администратор проверяет роль и назначения. Чужой ключ не одалживать.
- Два одинаковых пункта Monster Automation: выключите старое отдельное MCP-подключение, оставьте плагин.

## Для администратора

Этот репозиторий можно отдавать публично: в нём нет персональных ключей. Ключ сотрудник выпускает в кабинете. Не публикуйте установленную личную копию плагина и не кладите ключ в GitHub.
